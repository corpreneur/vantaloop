# Team Feedback — February 27, 2025

## Core Takeaway: 3-Layer Structure (Miami)

1. **Signal** ← Focus here
2. **Filtering** ← Focus here
3. **Action / Outcome** ← Too much emphasis currently

---

## Guiding Principles

- **Let the User Drive** — users must be in control of what's important, how they work, when they work, what they choose to work on.
- **Not a project management tool** — avoid PM-like patterns; we're not building "walking into the office."
- **"Quick Note" to capture signals from your head** 👍 — HUMINT capture is the killer feature. Gives app Day 1 value without any permissions.
- **The Conundrum**: The more "workflow" features you add, the more prescriptive the app becomes, which removes a sense of control.

---

## General Notes

- Too much text on screens; needs to be **much simpler** — minimal text, simple navigation, tappable actions.
- Currently feels like other AI/enterprise tools (layering Claude into your phone). Need to blend the **personal into the professional**.
- Screens should feel like **curated flows or streams** — seamless, easy to navigate, engage & take action within a few taps.

## Features to Include & Test

### Daily Brief
A snapshot of the day — a stream that includes schedule, calls, meetings, reminders, tasks, messages.

### User Modes
Different modes users curate based on priorities, mood, intentions:
- Locked In
- Being Creative
- Relaxing
- Family + Friends
- Learning

### User Controls
How users control and curate their modes, priorities, communications, streams of content:
- Filters
- Priorities
- Modes
- Contacts (Groupings / Labels)

### Communications
What normal text and email communications look like — group vs singular threads, how they are received, sent, organized, filtered, prioritized, how users respond.

### Media / Lifestyle Integrations
Music, podcasts, health/fitness tracking, research, articles — how do these fit into the experience?

### Profile / Contact Pages
Member profile vs contact profile — format and info to include (info, links, contacts, etc.).

## Screen-by-Screen Feedback (Stephen Hall)

### Context Setup
- No new feedback. Carry over: make "Pause" more prominent; solve for longer source lists.

### Home / Help Orient Me
- Screen is getting **very noisy** — reads like a PM app.
- Suggestion: surface the signal only; let the user tap in to discover details. Let them decide if/when they consume the noise.

### List Density
- Long term: make customizable.
- Preference: middle density as default, "Compact" view as optional pro-user toggle.

### Focused Brief
- **Really liked this.** Focused Brief + "Quick Note" could be the home screen; swipe up into signals.

### Filtering the Noise
- Previous week's concept was better — ironically this filtering screen is itself noisy.
- "Filtered noise" button should be as small as possible — if we're doing our job, users should rarely go there. More a point of pride / continual value indicator (like LinkedIn "X people searched your profile").

### Quick Look / Actioning Tasks Inline
- Encroaching on PM territory; complexity might not be worth it.

### Manual to Automatic
- **Great concept.** Could be used on almost any screen — dynamic action sheets mixing AI voice chat, text chat, and context button suggestions.
- Bottom transparent action sheet should follow the user everywhere throughout the app.

### Let the User Drive (Quick Note)
- ‼️ **Killer feature.** Solves the HUMINT problem — capturing signals from the user rather than their digital life. Gives app value on Day 1 without permissions. Must be deeply incorporated.

### Projects
- Project Members → maps to Circles concept. Complex; probably not a launch feature.
- Possible synergy with group chats — enforce mapping between group chat and members? Auto-create for discussions?

### Act vs Create / Set Me Up To Thrive
- Natural extension of profiles work. Natural place for preferences, business info, community/Accelerator aspects.
- Accelerator view: love easy checkboxes based on formula, real-time canvas, AI feedback.
- Open question: what if generation takes time? Do we park the user on the page until it completes?

### Entry Points
- Interesting to test; echoes Q2 2025 prototypes (some users liked, some hurdles with generalization).
- Navigation gets deep — user would need to commit to "browsing" formulas. Consider Instagram Reels-style browsing pattern.
